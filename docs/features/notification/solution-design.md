# Notification — solution design

Upstream design: Confluence 3886907646 and challenger-service `docs/features/notification/solution-design.md` (§12.1–12.3 audit fields, §12.6 audit log). This file records what this service implements and the local decisions.

## 1. API

Every public endpoint is under the versioned group and requires `Authorization: Bearer <access token>`. The JWT `sub` must be the account ObjectID (hex); anything else is 401. Every response sends `Cache-Control: private, no-store`. Mutating endpoints accept `Idempotency-Key`; the replay cache is keyed by caller + method + path + key (D15).

### `GET /api/v1/notifications`

| Param | Type | Notes |
|---|---|---|
| `tab` | `all` \| `activities` \| `system` | default `all` |
| `cursor` | opaque string | absent → first page |
| `limit` | int ≥ 1 | absent / `0` → 20; above `SVC_PAGINATION_MAX_LIMIT` → 400 |

```json
{
  "items": [
    {
      "id": "66f8c0e1a1b2c3d4e5f6a7b8",
      "kind": "challenge_published",
      "tab": "system",
      "title": "Run Club: 30 days of 5k",
      "body": "Lace up!",
      "image": { "type": "challenge", "url": "https://cdn/…/thumb.png" },
      "navigate": { "type": "challenge_detail", "challenge_id": "65a1b2c3d4e5f6a7b8c9d0e1" },
      "buttons": ["jump_in"],
      "is_read": false,
      "activity_at": "2026-09-29T03:00:00Z",
      "created_at": "2026-09-29T03:00:00Z"
    }
  ],
  "next_cursor": "eyJhIjoi…",
  "has_more": true
}
```

- Sort: `activity_at DESC, _id DESC`. `items` is always an array; `next_cursor` is omitted when `has_more` is false.
- `buttons` is `[]` once the buttons were hidden (`buttons_hidden_at` set); `is_read` = `read_at` set.
- **Cursor contract.** The cursor is a snapshot over `activity_at`, which a stack update moves forward. A card bumped while the client scrolls lands above the cursor and is not returned on later pages. Recovery: pull-to-refresh, or refetch from `cursor=""` when `summary.unread_total` changes.

### `GET /api/v1/notifications/summary`

| Param | Type | Notes |
|---|---|---|
| `tab` | `all` \| `activities` \| `system` | filters `groups` only |
| `tz` | IANA zone, e.g. `Asia/Saigon` | absent → UTC; offsets (`+07:00`), `Local`, unknown → 400 |

```json
{
  "unread_total": 3,
  "unread_by_tab": { "activities": 2, "system": 1 },
  "groups": { "today": 4, "this_week": 7, "earlier": 9 }
}
```

- `unread_by_tab` always covers both tabs; `groups` follow `tab` and count read + unread rows.
- Groups in `tz`: today = `[local midnight, ∞)`, this week = the previous 6 local days `[midnight − 6d, midnight)`, earlier = before that. Local-calendar arithmetic, so DST is handled. Known edge: in zones whose DST jump is at midnight (e.g. America/Havana), local midnight doesn't exist on that one day and the boundary shifts by an hour.
- **Mobile must send the device IANA zone.** Without `tz` the groups use UTC and won't match device-local grouping.
- **Count cap.** Every count stops at 100 (`summaryCountCap`); a value of 100 means "99+". `unread_total` is the sum of two capped counts, so it can reach 200 — clients render ≥ 100 as `99+`.
- The five counts run in parallel (errgroup); the request fails if any one fails.

### `PUT /api/v1/devices/{device_id}`

Registers the caller's push token for one device. `device_id` is generated by the app and stable per install (≤ 128 chars).

```json
{ "platform": "ios", "token": "<FCM registration token>", "app_version": "1.4.0" }
```

```json
{ "device_id": "b7a5…", "platform": "ios", "updated_at": "2026-09-29T10:00:00Z" }
```

- `platform` is `ios` | `android`; `token` is required (≤ 4096); `app_version` is optional (≤ 64). Unknown fields → 400.
- Upsert on `(user_id, device_id)`; the token is never echoed.
- A token held by any other row (another account after a re-login, or the caller's old install) is removed first, then the caller's row is written.
- A PUT that changes nothing (same platform, token, app version) moves `last_registered_at` only; `updated_at` and the response keep the previous value.

### `DELETE /api/v1/devices/{device_id}`

```json
{ "removed": true }
```

- Deletes the caller's row for `device_id`. A device that doesn't exist, or belongs to someone else, is `200` with `removed: false`.

### Internal API — `DELETE /api/v1/internal/notifications/users/{user_id}`

Account-deletion purge, called server-to-server by the job that also calls challenger's `DELETE /api/v1/internal/leaderboards/{challenge_id}/users/{user_id}`.

| | |
|---|---|
| Auth | `Internal-Secret: <SVC_NOTIFICATION_INTERNAL_API_SECRET>` (`middleware.SharedSecret`, constant-time). **Not** Bearer; no Idempotency middleware (the purge is idempotent). |
| Caller | `everfit-source: <service name>` (optional, ≤ 64) → `actor.id` on the audit entry |
| Mounted | only when the secret is set; empty → 404. Boot fails if a set secret is < 32 bytes. |
| Ingress | not under `/api/v1/notifications*` or `/api/v1/devices*`, so the public ingress never routes it to this service |

```json
{ "deleted_notifications": 12, "deleted_devices": 2 }
```

- Hard-deletes every `notifications` and `notification_devices` row of the user and writes one `purge` entry `{entity: user, entity_id: <user_id>, user_id, actor: {service, <caller>, internal_api}, count: <total>}`, all in one transaction.
- Idempotent: a repeat call returns `{0, 0}` and writes no entry.
- The user's existing audit entries are kept (proof of erasure; upstream Q-G5). Other users are untouched.

| Status | `code` | When |
|---|---|---|
| 400 | `INVALID_REQUEST` | `user_id` not a 24-hex non-zero ObjectID; `everfit-source` > 64 |
| 401 | `AUTH_REQUIRED` | missing / wrong `Internal-Secret` |
| 404 | `ROUTE_NOT_FOUND` | secret not configured |
| 500 | `INTERNAL_ERROR` | storage or audit failure — nothing is deleted |

### Errors

| Status | `code` | When |
|---|---|---|
| 400 | `INVALID_REQUEST` | bad `tab`, negative / over-max `limit`, bad `cursor`, bad `tz`; device: bad `platform`, empty `token`, `device_id` > 128 chars, unknown body field |
| 401 | `AUTH_TOKEN_MISSING` / `AUTH_TOKEN_INVALID` / `AUTH_TOKEN_EXPIRED` | Bearer middleware |
| 401 | `UNAUTHORIZED` | `sub` not a non-zero ObjectID |
| 500 | `INTERNAL_ERROR` | storage failure; audit write failure (the whole write rolls back) |

## 2. Data model

Collection `notifications`, one document per card, owned by this feature. Full struct in `internal/features/notification/service.go` (`Notification`, `Stack`, `StackActor`, `Actor`, `Image`, `Navigate`, `Source`, `PushState`). `Kind` values follow Confluence §3.0 (`friend_invite` … `challenge_ended`).

| Index | Keys | Used by |
|---|---|---|
| `notifications_feed` | `user_id, activity_at -1, _id -1` | feed + range counts, `tab=all` |
| `notifications_feed_tab` | `user_id, tab, activity_at -1, _id -1` | feed + range counts, one tab |
| `notifications_unread` | `user_id, tab, read_at` | unread counts |
| `notifications_ttl` | `created_at` (TTL 180 d) | retention |

`notifications_unread` is not partial: `partialFilterExpression` can't express `$exists: false`. The count cap bounds the FETCH cost.

### `notification_devices`

One row per `(user, device)`. Struct: `Device` in `service.go`.

| Field | Written |
|---|---|
| `user_id`, `device_id` | insert (upsert filter) |
| `platform`, `token`, `app_version` | every PUT that changes one of them; an empty `app_version` is `$unset` |
| `last_registered_at` | every PUT — stale-token cleanup reads this, not `updated_at` |
| `created_at`, `created_by` | `$setOnInsert` only |
| `updated_at`, `updated_by` | insert and every PUT that changes a field |

`created_by` / `updated_by` = `{type: user, id: <account_id>, via: api}`.

| Index | Keys | Opts | Used by |
|---|---|---|---|
| `devices_user_device` | `user_id, device_id` | unique | find / upsert the caller's row |
| `devices_token` | `token` | unique | find the current holder of a token before eviction |

### `notification_audit_logs`

Append-only; only this feature writes it. Struct: `AuditLog` in `service.go` (upstream §12.6 shape; `changes` is typed `map[string]FieldChange{from, to, changed}`).

| Index | Keys | Opts | Serves |
|---|---|---|---|
| `audit_entity` | `entity, entity_id, at -1` | — | history of one record |
| `audit_user` | `user_id, at -1` | partial `user_id $exists` | everything that happened to one user's data |
| `audit_dedupe` | `audit_key` | unique, partial `audit_key $exists` | duplicate entries from retried writers |
| `audit_ttl` | `at` | TTL = `auditRetention` (= `retention`, 180 d) | bounded storage |

Entries written by this card:

| Operation | Entry | `user_id` | `changes` |
|---|---|---|---|
| PUT, new row | `create` on the device | caller | — |
| PUT, platform / app version / token changed | `update` on the device | caller | `platform`, `app_version` as `{from, to}`; `token` as `{changed: true}` |
| PUT, nothing changed | **none** | — | — |
| PUT, token held by another row | `delete` on that row, then the caller's `create` / `update` | the evicted row's owner (actor = caller) | — |
| DELETE, row exists | `delete` on the device | caller | — |
| DELETE, no row | **none** | — | — |
| Purge, rows deleted | one `purge` on the user (`entity: user`) | purged user | — (`count` = notifications + devices) |
| Purge, nothing to delete | **none** | — | — |

### Audit rules (the helper in `service.go`)

- **Same transaction.** `Service.runAudited` runs the data writes and `recordAudit` in one `Repo.WithTransaction` (`mongox.Client.WithTransaction` → driver `Session.WithTransaction`, which re-runs the callback on `TransientTransactionError`). A failed entry fails the request and nothing is written.
- **Allow-list per entity** (`auditFields`): anything not listed is dropped; masked fields (`token`) are stored as `{changed: true}` whatever the caller passed.
- **No-ops write nothing** (`auditIsNoOp`): an `update` with no allow-listed change and no `count`, or a `purge` with `count = 0`.
- **Stamps**: `request_id` from `middleware.RequestIDFromContext`, `trace_id` from the active span (absent without OTel), `at` = the write's `now`, so it matches `updated_at`.
- **Retries**: an entry with an `audit_key` that already exists returns `errAuditRecorded`; `runAudited` treats that as success (the write already committed). Device writes set no `audit_key`; Kafka / Temporal writers will.
- Reads, TTL expiry and refresh-only PUTs are not audited. No PII: no token value, no title / body.

## 3. Writer invariants (for later cards)

- Every insert sets `created_at` — TTL skips documents without it, so they'd be kept forever — and `activity_at`.
- `user_id` = JWT `sub` (account ObjectID).
- `activity_at` is never in the future — "today" is `[local midnight, ∞)` and the feed sorts on it, so a future-dated row sits at the top.
- Un-read = `$unset: {read_at: ""}`, never `$set: {read_at: null}`.
- Upserts rely on `_id,omitempty` / `created_at,omitempty` + `$setOnInsert` (mongo.md §6).
- Every data write goes through `runAudited` + `recordAudit` (§2 audit rules), including a no-op check before writing.

Sanity check after any writer card:

```js
db.notifications.countDocuments({ created_at: { $exists: false } })        // must be 0
db.notification_devices.countDocuments({ created_at: { $exists: false } }) // must be 0
```

## 4. Retention runbook

Retention is `const retention` in `indexes.go` (Confluence §7 `RetentionDays`), deliberately not an env; `auditRetention` is defined as `retention`, so audit entries never expire before the data they describe. Old and new pods both run `EnsureSpecs` at boot; a TTL mismatch → `IndexOptionsConflict` → crashloop. To change it:

1. Before the deploy, change the live indexes:
   ```js
   db.runCommand({ collMod: "notifications", index: { name: "notifications_ttl", expireAfterSeconds: <days * 86400> } })
   db.runCommand({ collMod: "notification_audit_logs", index: { name: "audit_ttl", expireAfterSeconds: <days * 86400> } })
   ```
2. Ship the code change with the same value.

## 5. Local decisions

| # | Decision | Why |
|---|---|---|
| D1 | Per-feature `feedCursor{activity_at, _id}`, strict parse, ms precision | sort key differs from the shared cursor (mongo.md §2) |
| D2 | `limit` ceiling = shared `SVC_PAGINATION_MAX_LIMIT`, enforced in Service | http.md §11 |
| D3 | Summary = 5 parallel counts, each capped at 100 | bounded cost per request |
| D4 | Stack members are `StackActor`; `Actor{type,id,via}` is for `*_by` | name clash between §2.2 and §12.1 |
| D8 | `buttons = []` when hidden; `is_read = read_at != nil` | Confluence Fig. 15 |
| D9 | `tz` IANA only; empty → UTC; week start = local midnight − 6 days | DST-safe |
| D10 | Retention is a const | a tunable TTL crashloops on change |
| D11 | JWT secrets required at boot | every route is authed; otherwise a silent 404 |
| D12 | `Cache-Control: private, no-store` on every response | personalised data |
| D13 | Audit TTL is `const auditRetention = retention`, not the card's `NOTIFICATION_AUDIT_RETENTION_DAYS` env | same crashloop risk as D10; "audit ≥ data retention" holds by construction instead of a boot check |
| D14 | `Repo` covers `notifications` + `notification_devices` + `WithTransaction`; `AuditWriter` is its own port | upstream §2.1 has one Repo for the feature's collections; the audit port is shared by every future writer and tests fail it on its own |
| D15 | Idempotency runs after `BearerAuth`; replay key = `idempotency:<user>:<METHOD> <path>:<key>` | before, the key was global — a reused key replayed another user's response (CHAL-399 follow-up) |
| D16 | Token eviction deletes the other holder **before** the upsert, in the same transaction | the unique `devices_token` index rejects the upsert otherwise |
| D17 | Eviction entry: `user_id` = the evicted row's owner, `actor` = the caller | the owner's history shows the removal; the actor shows who caused it |
| D18 | `PUT` returns 200 for both create and update | one response shape; the audit log records which one happened |
| D19 | Purge path is `/api/v1/internal/notifications/users/{user_id}` (card: `/internal/...`) | same shape as challenger's internal routes, which also live in the versioned group; inherits Throttle |
| D20 | Secret env is `SVC_NOTIFICATION_INTERNAL_API_SECRET` (card: `NOTIFICATION_INTERNAL_API_SECRET`) | this repo's `SVC_` prefix; feature-namespaced like `CHALLENGER_LEADERBOARD_INTERNAL_API_SECRET` |
| D21 | A set secret must be ≥ 32 bytes | it authorises a hard delete; empty stays allowed (route off) |
| D22 | Purge deletes notifications and devices in one transaction | "audit failure → nothing deleted" (card AC); a user's rows are bounded by the 180-day TTL, well inside transaction limits |

Deviations from `.claude/rules`: no `log.go` / `localization.go` yet (nothing logs, no feature code); request-shape rejects (limit, cursor, caller id) use `apperr.*` directly, only `tz` is a sentinel.
